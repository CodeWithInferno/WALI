# 0015: Canonicalize hostile media in credential-free sandboxes

- status: partially_superseded
- date: 2026-09-01
- owner_role: media_worker_maintainer
- accepted_by: project_owner
- approval_reference: project-owner AFK marketplace implementation directive 2026-09-01
- superseded_by: 0017

## Context

Media containers exercise complex native parsers. File extensions, MIME headers,
checksums, antivirus results, and creator identity do not make uploaded bytes
safe. Server-side and local media processing must assume malicious files while
still producing efficient video wallpaper artifacts.

## Decision

Accept only the bounded MOV/MP4 policy in
`docs/security/media-policy.yml`. A host control worker downloads opaque bytes
without parsing them, then launches a fresh rootless, networkless media sandbox
with read-only input, bounded scratch/output, read-only root filesystem, dropped
capabilities, no devices, no host mounts, and no credentials. The sandbox fully
decodes and re-encodes supported input to canonical output while stripping
audio, metadata, subtitles, attachments, chapters, data tracks, external
references, and every unsupported stream.

A separate fresh verifier sandbox independently inspects the generated bytes.
Only bounded JSON facts cross to the host; the host validates schema, sizes,
roles, and digests before uploading immutable artifacts. Classification receives
only seven bounded raster frames produced by the media sandbox and runs in a
separate networkless container. Model output is an untrusted taxonomy suggestion,
never a rights, safety, or publication decision.

On macOS, every local import and catalog download follows the same principle:
the private sandboxed transcoder inspects/canonicalizes untrusted media, and the
agent independently verifies destination bytes before content-store publication.
No process with Full Disk Access parses those bytes.

## Invariants

- Intake enforcement covers actual signature/container, track count/type,
  codec, dimensions, duration, frame rate, declared and decoded sizes, and
  decompression/resource limits; `Content-Type` is never sufficient.
- Server media/verifier/classifier sandboxes have no network, Supabase secret,
  container-runtime socket, inherited credential, inbound port, or unrelated
  host path.
- One attempt receives fresh process/container state and an opaque directory;
  time, CPU, memory, process, output, and disk limits are mandatory.
- Canonical playback output is a single silent video track in a bounded MP4
  plus raster JPEG/PNG posters and thumbnails. Marketplace codec, bit depth,
  and long-edge policy are defined by ADR 0017.
- SVG, PDF, animated images, archives, playlists, scripts, shaders, fonts,
  plug-ins, encrypted tracks, and dynamic/external references are rejected.
- Worker and model images, FFmpeg build/flags, arguments policy, model weights,
  taxonomy, and every binary artifact are immutable-digest pinned and licensed.
- A sandbox claim cannot publish; independent verification, current generation,
  moderation, immutable storage, and signing are still required.
- Failure or timeout preserves creator source until retention policy applies and
  emits only a stable safe error code.

## Partially superseded clauses

ADR 0017 replaces the H.264 MP4 codec clause for marketplace sandbox output.
Hostile decode/re-encode, independent verification, audio stripping, and
sandbox isolation remain in force.

## Alternatives considered

- Validating extensions and MIME types is cheap but does not exercise or remove
  malicious container structure.
- A long-lived transcoder sharing worker credentials would expose backend
  authority to parser compromise.
- Running FFmpeg directly in an Edge Function is unbounded and couples media
  work to a short-request platform.
- Antivirus-only admission provides an additional signal but cannot prove safe
  parser behavior or deterministic canonical output.

## Consequences

Processing needs rootless container support, pinned images, separate verifier
logic, resource budgeting, hostile-corpus tests, and regular media dependency
updates. Throughput is lower than a trusted long-lived decoder, but incidents
are constrained and workers remain disposable.

## Migration and rollback

Policy revisions create new processing attempts and release editions; published
artifacts are never rewritten in place. A vulnerable image or codec pauses new
processing, revokes the image digest, rebuilds from pinned source, and reprocesses
affected unpublished attempts. A confirmed malicious published release follows
the signed critical-revocation runbook. Disabling classification falls back to
creator and moderator taxonomy without blocking canonical media processing.

## Verification

- The checked-in media policy and generated constants share a recorded digest.
- Hostile corpus tests cover parser crashes, bombs, excessive tracks/atoms,
  malformed timing, unsupported codecs, metadata, external references, and
  truncated/changing input.
- Sandbox launch tests prove network denial, credential absence, mount limits,
  capability drop, quotas, and cleanup after kill/restart.
- Local tests use copied temporary media and never mutate live wallpaper stores.
